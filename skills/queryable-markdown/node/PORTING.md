# Porting mdq.py to Node (read-only batch)

Source of truth: `../scripts/mdq.py` (Python 3, mdq.py/4). Goal: byte-for-byte equal JSON for read commands on documents that carry a contract. Parity is checked by `bun run parity` against golden output captured from Python on friday-relay `docs/`.

## Rules (all modules)
1. Port function-for-function. Keep Python names (snake_case) for functions, parameters (as positional args or one options object with the same names), and dict/dataclass keys. Do not rename, merge or "improve".
2. Files are ESM `.mjs` in `src/`. Dependencies allowed: `markdown-it` (use `new MarkdownIt("commonmark", {html:false})`, `.enable("table")` where Python does), `yaml` (use `{ version: "1.1", uniqueKeys: true, maxAliasCount: 0 }` to mimic PyYAML SafeLoader + the alias/duplicate-key bans), node builtins. Nothing else.
3. Use `src/common.mjs` (diagnostic, sha256, normalized_json, line_set, py_strip/py_lstrip/py_rstrip, splitlines_keepends, utf8_len, casefold, compile_py/PyPattern for every Python regex coming from a *profile*) and `src/types.mjs` (dataclass equivalents).
   - Regexes written inside mdq.py itself become ordinary JS RegExp literals; patterns coming from profiles/contracts must go through `compile_py` (they are Python syntax).
   - `PyPattern` exposes `.groups`, `.groupindex`, `.search/.match/.fullmatch/.finditer` returning `PyMatch` with `.group(k)`, `.start(k)`, `.end(k)`.
4. Python → JS hazards to handle explicitly (comment them where relevant): `str.strip()` vs `trim()` (use py_strip), `splitlines` (use splitlines_keepends), dict ordering (insertion order — keep it), `sorted()` on str (code point order: `codepoint_compare`), `set` iteration order is never relied on in Python output (they sort) – keep the same sorts, integer division, `round`, float printing (output JSON is compared after parsing so `1.0` vs `1` is fine), string indexing by code point (Python) vs UTF-16 unit (JS): lines/columns/byte offsets that are exposed in output must match for non-BMP text — use `Array.from(...)` or `utf8_len` where Python uses `len()`/`.encode()`.
5. Unsupported-in-batch-1 features (temporary selectors for profile-free documents: `prepare_temporary_profile`, `line_local_*`, `temporary_*`, `optimize`, `set`, `index` writes, semantic search): do not port. Where a ported function would call them, call `unsupported_in_node(feature)` from `common.mjs`-style helper defined in your module and fail closed with diagnostic code `unsupported_in_node` (severity error). Never silently return a different answer.
6. Every function exported must keep the Python name. Cross-module imports are by those names:
   - `profile.mjs`: load_yaml, shared_profile_path, load_shared_profile, unique_json_object, top_level_json_key_present, normalize_label, field_name_from_header, safe_compile, validate_group, match_group, parse_profile, validate_profile, plus constants (MAX_PROFILE_BYTES, MAX_PATTERN_LENGTH, MAX_REGEX_LINE, REGEX_TIMEOUT_SECONDS, PROFILE_COMMENT_RE, MARKER_RE, ATX_HEADING_RE, SETEXT_RE, GENERIC_ID_PATTERN, GENERIC_ID_RE, TEMPORARY_PROFILE_PREFIX, SHARED_PROFILE_PREFIX, PROFILE_REFERENCE_RE, INFERRED_KEY_LABELS, …all module constants of mdq.py lines 36-80).
   - `document.mjs`: markdown_literal_regions, parse_document, read_document, inline_code_ranges, position_is_literal, scan_source_layers, analyze_markdown, analyze_tables, table_key_candidates, table_profile.
   - `records.mjs`: regex_value, compile_profile_pattern, strip_label_prefix, label_occurrences, resolve_scalar, key_from_heading, heading_is_boundary, nearest_marker, collect_boundaries, section_values, regex_field_values, apply_value_pattern, extract_fields, declared_key, build_records, serialize_record, extract_current, index_path, load_valid_index, records_for_query, status_for, error_diagnostics.
   - `output.mjs`: emit, output_fields, project_output_payload, output_selection_diagnostics, iter_result_diagnostics, compact_*, actionable_diagnostics, minimal_query_payload, emit_query_result, emit_collection_result.
   - `query.mjs`: command_query (also serves `get`), searchable_values, query_matches, project_query_record, query_quality, command_run, command_verify_queries, run_internal_mdq, sample_record_keys.
   - `collection.mjs`: collection_diagnostic, collection_paths, collection_record, command_scan (also serves `find`), command_search, command_inspect, command_validate, command_check.
   - `cli.mjs`: build_parser equivalent + main (hand-written argv parser for: inspect, validate, query, get, run, verify, check, search, scan, find; options exactly as in `build_parser`), exits with the same return codes.
7. When you need a helper from a range you do not own, read its Python body to learn the exact signature and semantics, import it by Python name from the owning module, and do not reimplement it.
8. Quality bar: `node --check` every file you write; write a tiny smoke script under `node/smoke/<yourmodule>.mjs` that exercises your functions on real inputs where possible (e.g. real files under /home/claude/friday-relay/docs) and compare against Python (`uv run ../scripts/mdq.py ...`) where a CLI-visible answer exists. Report anything you could not port or were unsure about, with line numbers.
9. Do not edit `src/common.mjs` or `src/types.mjs`; if you need a helper added, list it in your report. Do not call any `mcp__hearthbot__*` tools. Do not commit or push.
